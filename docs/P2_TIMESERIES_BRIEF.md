# Claude 구현 지시서 — P2 첫 시계열 학습 실행

## 작업 지시

> 프로젝트 루트의 `CLAUDE.md`, `docs/CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/CONTRACTS.md`, `docs/SCREEN_DESIGN.md`, `docs/PROGRESS.md`와 이 지시서를 읽고 **CSV → 실제 전처리 → 시간순 분할 → XGBoost CPU 학습 → 평가·저장**을 기존 화면에 연결해 줘. S4에서 승인한 설정으로 실행하고, S5에서 실제 작업 단계와 결과를 확인할 수 있어야 해. 현재 코드를 먼저 조사하고 기존 Registry·Adapter·검증·승인·작업 상태 서비스를 재사용해 줘.

이번 완료 기준은 실제 계산된 예측값과 MAE·RMSE가 저장되는 것이다. 명령은 프로젝트 루트에서 실행한다. 문서 안의 상대 링크는 `docs/` 기준이다.

## 기존 구조와 이번 변경 위치

| 기존 위치 | 역할과 연결할 작업 |
|---|---|
| `frontend/` | S1~S4 설정 흐름을 사용하고 S5 실행·결과를 최소 연결 |
| `src/mlworkbench/api/` | 승인한 계획 제출·상태·결과 조회의 웹 진입점 |
| `src/mlworkbench/app/` | 데이터·초안·승인·실행을 조율하는 공통 서비스 |
| `src/mlworkbench/core/` | 계약·Registry·검증·승인 해시 |
| `src/mlworkbench/plugins/` | ADD-2 전처리 계약에 연결하는 실제 전처리와 XGBoost 어댑터 |
| `src/mlworkbench/pipelines/` | 시계열 분할·입출력·평가를 조합하는 실행 경로. 필요할 때 생성 |
| `src/mlworkbench/runner/` | 별도 CPU 프로세스의 실행·상태·종료. 필요할 때 생성 |

현재 모듈의 책임을 유지하며 필요한 파일을 추가한다. 서로 공유하는 파일을 반영하기 직전에 다시 읽고 다른 작업의 변경과 병합한다. 설치가 필요한 패키지와 지원 버전, 인터페이스 변경은 먼저 계약 문서와 optional dependency에 기록한다. 실제 설치·학습은 세션에서 받은 사용자 승인과 실행 환경 권한을 확인한 범위에서 진행한다.

## 첫 실행을 지원할 기능

- CSV 시계열, 수치형 타깃, 선택적 설비 구분 열, 시간 단위 horizon을 지원한다. 우선 15분·30분 예측을 같은 예제에서 확인한다. timestamp 해석과 시간대 처리, 중복 시각과 누락 시각의 정책을 명시한다.
- 기존 ID를 재사용하여 그룹·시간 정렬, 세션 분리, 리샘플링, 결측 처리, lag를 실제 구현에 연결한다. `ts.scale`은 사용하는 경우에만 train 전용 fit으로 연결한다. XGBoost를 정확한 버전과 파라미터로 실행한다. 다른 미구현 전처리를 선택하면 사유와 함께 최종 검증에서 차단한다.
- Pandas·NumPy·scikit-learn 등 기존 라이브러리와 ADD-2 어댑터 계약을 사용한다. 라이브러리 호출은 Python 어댑터에 둔다. 구현과 테스트가 완료된 항목만 `ready`로 전환한다. 카탈로그 ID를 바꾸면 저장된 초안에 영향이 있으므로 기존 명세의 호환성을 먼저 확인한다.
- 기본 Mock 계획의 `ts.missing`이 선형 보간을 선택하는지 확인한다. 미래 관측을 사용하는 보간은 예측용 기본안에서 사용할 수 없다. 과거값으로만 채우는 정책을 추천·스키마·실제 어댑터에 일관되게 적용하고, 이전 초안에는 변경이 필요한 항목을 안내한다.

## 데이터 분할과 평가 계약

1. 전체 입력의 시간 범위에서 그룹 간 동일 시각이 다른 분할에 걸치지 않도록 시간 경계를 정하고, 학습·검증·테스트의 실제 행 식별자와 경계를 저장한다. 학습량만 바꾼 경우 동일한 검증·테스트 샘플을 사용한다.
2. `최근 N일`은 전체 데이터의 마지막 날이 아니라 **학습 구간의 마지막 시각**을 기준으로 적용한다. 필요한 과거 이력 처리 방식을 기록하고, 실제 사용한 기간과 전처리 후 유효 학습 샘플 수를 표시한다.
3. 피처를 만들 때 그룹·세션 경계와 관측 가능 시점을 지킨다. 리샘플링 구간의 표시 시각·닫힘 방향을 고정하고, 예측 기준 시각보다 미래인 관측값을 피처에 넣지 않는다. 타깃은 정확한 horizon의 미래 시점에 맞춘다. 세션을 넘는 타깃과 학습 라벨이 다음 분할로 넘어가는 행은 제거한다.
4. 테스트 평가는 시간에 따라 새 관측이 들어오는 rolling-origin 방식으로 정의한다. 각 예측 기준 시각까지의 관측 이력만 피처에 사용한다. 스케일러·결측치 추정·인코딩의 fit과 모델 학습은 학습 데이터에서만 수행한다. 검증·테스트에서 재학습하지 않는다.
5. XGBoost와 같은 시각·그룹·horizon·평가 샘플에서 직전값 기준 예측을 계산한다. MAE·RMSE와 선택된 horizon별·설비별 집계를 저장한다. R²·sMAPE를 제공한다면 계산식·집계·0 분모 및 계산 불가 처리도 테스트한다. 구현 전인 평가 선택지는 실행 검증에서 알려준다.

## 승인 → 실행 → 결과

- 화면이 보내는 계획 ID와 해시를 서버가 현재 초안·활성 승인·데이터 버전·플러그인 상태와 대조한다. 이미 있는 `JobService.submit`의 검증 및 중복 제출 방지를 재사용한다. 승인 토큰은 현재 해시만 저장되어 있으므로 복구할 수 없다. 서버 전용 제출 경로와 기존 토큰 기반 경로가 같은 검증·트랜잭션을 사용하도록 필요한 부분만 정리한다. 임의의 계획 ID만으로 승인 검사를 통과할 수 없어야 한다.
- S4의 학습 시작은 실제 worker가 준비된 경우 연결한다. 두 번 클릭하거나 요청을 재전송해도 동일 승인에서 실행 한 건과 worker 한 개를 만든다. 실행 등록·파일 저장·프로세스 시작 중 실패하면 실패 상태와 원인을 남기고, 시작되지 않은 작업이 계속 대기 상태로 남지 않게 한다.
- `RunEvent`를 준비·전처리·학습·평가·저장 단계에서 실제 발행한다. S5는 상태·단계·경과 시간·오류와 완료 지표를 보여준다. 진행률은 관측한 값이 있을 때 표시한다. 앱의 업로드·상태 조회는 학습 중에도 응답한다.
- 기존 앱 종료 정책과 작업 취소·서버 재시작 시의 실행 상태를 연결한다. 종료한 프로세스와 실행 기록이 어긋나지 않게 한다. Windows spawn을 포함해 확인한다.
- 승인 설정, 실제 분할, 데이터 매니페스트·해시, 플러그인 및 라이브러리 버전, seed, fitted 전처리 상태, 모델, 예측값, 지표·평가 메타데이터와 로그를 `workspace/experiments/<run_id>/`에 저장한다. 예측에는 설비·기준 시각·예측 대상 시각·horizon·실제값·예측값을 연결한다. 저장한 모델과 전처리는 이후 새 CSV 적용에서 불러올 수 있어야 한다.

## 검증과 완료 기준

- 예제 `outputs/workbench-sensor-example/motor_sensor_example.csv`가 있으면 이를 사용한다. 시간열은 `timestamp`, 설비 열은 `device_id`, 타깃은 `temperature_c`다. S1~S4에서 15분·30분, 전체/최근 30일, 시간순 70/15/15, MAE·RMSE·직전값을 설정한다. 승인 후 S5에서 실제 학습 완료와 예측·지표 저장을 확인한다.
- 필요한 회귀 테스트를 먼저 마련하고, 미래값을 바꿔도 과거 피처가 달라지지 않는지, 그룹·세션 경계와 horizon 분할 누수가 차단되는지, 전처리 fit이 train 전용인지 확인한다. 학습량만 바꾸는 두 실행에서 평가 분할이 같은지 확인한다.
- 승인 없음·변경된 승인·중복 요청·프로세스 실패와 재시작·취소를 확인한다. 기존 LLM·MCP·S1~S4 및 ADD 테스트가 통과해야 한다. 실제 CPU 학습 통합 테스트와 프런트엔드 빌드·브라우저 확인 결과를 기록한다.
- 실행된 설정과 같은 seed로 재실행하고 지표 허용 오차와 실제 차이를 기록한다. baseline보다 좋은 성능을 완료 조건으로 강제하지 않는다. 지표가 정상 계산되고 저장된 예측으로 다시 계산한 값과 맞아야 한다.
- 이번 변경·테스트·실행 증거와 남은 항목을 [PROGRESS.md](PROGRESS.md)에 추가한다. P2 전체에는 이후 모델을 불러와 **새 CSV 예측·다운로드**까지 포함한다. 첫 학습만 끝난 경우 그 항목은 미완료로 유지한다.
