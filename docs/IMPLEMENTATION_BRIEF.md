# Claude 첫 구현 지시서 — P0

## Claude에 전달할 지시

> `CLAUDE.md`, `REQUIREMENTS.md`, `SCREEN_DESIGN.md`, `ARCHITECTURE.md`, `CONTRACTS.md`, `PROGRESS.md`, `IMPLEMENTATION_BRIEF.md`를 읽고 P0를 구현해 줘. `CONTRACTS.md` §11을 화면 검토 후 계약 기준으로 사용하고, 기존 의사코드와 예시 YAML의 해당 필드를 맞춰 줘. 아래 범위와 완료 기준에 따라 실제 테스트를 실행하고 `PROGRESS.md`에 결과를 남겨 줘.

## 화면 설계 검수 기준

첫 화면의 좌우 구성, 전처리 추천 이유와 체크 선택, 학습 설정의 모델·학습량·분할 및 평가, 승인과 실제 진행 단계, 결과 비교에서 새 데이터 적용까지의 동선을 구현 기준으로 사용한다. 시계열과 비전의 전체 동선은 `SCREEN_DESIGN.md`를 따르며, 실제 코드는 단계별로 진행한다.

## P0 구현 범위

1. Python 패키지, 최소 의존성, `pytest`, CLI `doctor`, `plugins list`, `providers list`, `plan validate`를 구성한다.
2. 데이터셋·프로파일·플러그인·Provider 계약과 Registry, `MockProvider`, 읽기 전용 MCP 도구 카탈로그 계약을 구현한다. Mock의 예시 플러그인과 실제 실행 가능 상태를 구분한다.
3. `DraftPlan`, `PlanProposal`, 승인 가능한 실행 계획과 `ApprovedSnapshot`의 경계를 구현한다. 목표 필드는 `user_goal`에 둔다. `train_budget`, 분할, 평가 방식은 구조적으로 구분한다. 구조화된 검증 오류와 한글 플러그인 메타데이터를 지원한다. 요약이나 추천 이유의 편집은 학습 설정 변경과 구분한다.
4. 승인 기록과 제출 권한을 로컬 저장소에서 검증한다. 서버가 확정한 데이터 버전, 정확한 플러그인 버전과 실행 설정을 같은 스냅샷 및 해시에 묶는다. 학습량을 실제 데이터에 적용하거나 분할을 계산하는 동작은 해당 파이프라인 단계에서 구현한다. P0에서는 합성 매니페스트나 테스트용 분할로 승인 흐름을 검증한다.
5. 대상 상태와 진행 이벤트의 타입을 정의한다. CLI와 테스트에서 확인할 수 있는 계약까지만 구현한다. 실제 실행기의 이벤트 발행과 화면 폴링은 P2 범위다.

P0에서는 로컬 저장과 Mock으로 검증한다. 웹 화면, 실제 업로드 처리·추천 API 호출, MCP 전송, 학습 worker, 배치 추론 및 MLflow 연동은 후속 단계에 둔다.

## 완료 확인

- `doctor`, 목록 명령, 합성 추천안 검증이 실제로 실행된다. `MockProvider`의 정형 추천안이 검증과 승인 흐름으로 연결된다.
- 모델이 비어 있는 수동 초안에서 전처리를 편집할 수 있다. 제출 가능한 계획에는 모델과 정확한 버전이 필요하다. 미등록·미설치·비호환 플러그인과 잘못된 파라미터가 차단된다.
- 학습량·분할·평가가 승인 설정에 포함된다. 실행에 영향을 주는 설정을 변경하면 이전 승인을 새 요청에서 사용할 수 없다. 승인 없이 제출할 수 없고, 같은 유효 요청을 재전송해도 실행 등록은 중복되지 않는다.
- `pytest` 결과와 실제 실행한 명령, 변경한 파일, 남은 항목을 `PROGRESS.md`에 기록한다.
