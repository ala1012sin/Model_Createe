# 추가 요구사항 ADD-UX 적용 — 설계 기록 (2026-11-20, Claude 작성)

> 근거: `REQUIREMENTS.md` §5 ADD-UX-01~11. 사용자 지시: "수정 먼저 일단 하고 다음 계획 생각하자".
> 세 묶음으로 나눠 묶음마다 테스트·브라우저 확인 후 반영한다. 1차 = 화면만 고치는 것, 2차 = 삭제·이름(데이터 변경), 3차 = 실행기 자동 설치.

## 1차 (03·04·05·08·09·10·11)

| ID | 결정 | 이유·영향 |
|---|---|---|
| 05 | `needs_sheet` = 엑셀 · 시트 미선택 · **상태 REGISTERED**일 때만. 업로드 실패한 엑셀은 '업로드 실패' | 상태 표시 버그 |
| 08 | 문서 스크롤 영역에 `scrollbar-gutter: stable` — 스크롤바 유무와 상관없이 폭 고정 | 데이터셋을 바꿀 때 박스가 흔들리던 원인(세로 스크롤바 생김·사라짐) |
| 09 | 목표 저장이 오류 없이 끝나면 화면 위 알림(토스트) '목표를 저장했습니다 — 전처리로 이동합니다' 후 전처리로 자동 이동. 저장했지만 오류 항목이 있으면 이동하지 않고 그 자리에서 표시. 토스트는 앱 공통(화면을 넘어가도 잠깐 유지, 약 3초) | S2→S3('저장하고 학습 설정으로')와 같은 흐름 |
| 10 | 각 단계 화면 제목 위에 '← 이전 단계' 링크: 전처리 → 데이터셋·목표, 학습 설정 → 전처리, 확인·실행 → 학습 설정, 실행 상세 → 실행·결과 목록, 새 데이터 적용(모델을 미리 고른 경우) → 그 실행 상세. 마우스 '뒤로' 버튼·Alt+← 는 앱 창에서도 브라우저 기록을 따름(이동은 해시 주소라 기록이 남음) | 앱 창에는 브라우저 뒤로가기 버튼이 없음. 저장하지 않은 변경 경고는 기존 이동과 같음 |
| 11 | 시간 간격 파라미터(스키마 pattern이 `^\d+(s|min|h|d)$`인 항목)와 S1 예측 구간 직접 입력을 **숫자 입력 + 단위 선택(초·분·시간·일, 기본 분)** 으로. 저장 값은 기존 형식(예: 60min) 그대로 | 계약·저장 형식·검증 변경 없음, 화면만 |
| 04 | 내장 모델 스키마에 `default`(XGBoost 트리 300 · 깊이 6 · 학습률 0.1 = 어댑터 기본값과 같게, 테스트로 고정). 입력란이 비어 있으면 회색 '기본값 300'으로 보이고 '비워 두면 기본값' 안내, 값을 넣었으면 '기본값으로' 버튼(비움) | 비워 둔 값은 지금처럼 어댑터 기본값 사용 — 승인 해시·저장 계획 형식 변화 없음 |
| 03 | 창 닫기(×)를 누르면 앱 안 확인 창: '앱을 종료합니다'. 실행 중·대기 중 학습이 있으면 'N개가 중단·취소됩니다(대기 실행은 다음에 켜면 이어서 시작)' 함께 표시. [종료] [취소]. Alt+F4 등 창 밖 종료는 이번 범위 밖(기록) | 실행기 쪽 네이티브 확인은 3차에서 함께 검토 |
