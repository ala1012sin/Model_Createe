# Claude 구현 지시서 — P1 CSV 등록·프로파일링

> `CLAUDE.md`, `PROGRESS.md`, `REQUIREMENTS.md`, `SCREEN_DESIGN.md`의 S1, `CONTRACTS.md`를 읽고 이번 작업에서는 **CSV 등록 및 로컬 프로파일링**을 구현해 줘. 기존 P0 서비스와 계약을 재사용해 나중에 S1 첫 화면에서 붙일 수 있는 호출 경로를 만들어 줘. 합성 CSV로 테스트를 실행하고 `PROGRESS.md`에 실제 결과를 남겨 줘.

## 이번에 구현할 범위

1. 기존 `DatasetService`를 통해 CSV 입력을 등록한다. 로컬 작업 공간에 서버가 관리하는 경로로 저장하고, 저장한 바이트로 데이터 버전 해시를 계산한다. 원래 파일명은 로컬 화면용 표시값으로 취급한다. 명시적인 등록·분석 재시도에서 부분 파일이나 성공으로 보이는 실패 레코드가 남지 않도록 한다.
2. `UPLOADING → REGISTERED → PROFILING → PROFILED` 상태와 계약에 있는 단계별 실패 상태를 사용한다. 빈 파일, 깨진 인코딩, 잘못된 헤더나 해석할 수 없는 행의 처리 기준을 정하고 오류를 사용자용 코드와 한글 설명으로 전달한다. 시간열 후보가 없는 정상 CSV는 프로파일 결과와 함께 안내한다.
3. S1 오른쪽 패널에 필요한 로컬 프로파일을 만든다. 행 수, 컬럼명과 추정 타입, 결측률, 중복 행 수, 시간열 후보와 간격 추정을 지원한다. 시간 정보가 부족하면 추정 불가를 돌려준다. 로컬 프로파일은 재조회 시 다시 읽을 수 있어야 한다.
4. 전송용 `SafeProfile`은 허용한 필드와 집계값만 모아 별도로 만든다. 원시 헤더는 기본적으로 `column_1` 같은 별칭으로 바꾸고, 시간열 후보 등은 같은 별칭으로 참조한다. 원래 파일명, 절대경로, 개별 셀 값, 원시 헤더, 예외 원문은 전송 요약에 담지 않는다. 로컬 UI용 실제 컬럼명은 별도로 유지한다.

## 완료 확인

- 합성 CSV를 실제 등록하고 분석하면 버전 해시, 행 수, 컬럼 타입, 결측률, 시간 후보가 조회된다. 같은 파일 바이트의 해시는 일치하고 데이터가 바뀌면 달라진다.
- 실패 입력의 상태와 오류 이유가 조회되고, 정상 입력으로 다시 시도하는 흐름을 확인한다.
- 한글 헤더가 있는 CSV와 시간열 후보가 없는 CSV를 확인한다. 경로·키처럼 보이는 헤더와 고유 문자열 셀 값을 넣어도 직렬화된 `SafeProfile`에 노출되지 않는다.
- 새 CSV 테스트와 P0 회귀 테스트를 실행한 명령, 운영체제·Python 버전, 실제 통과·실패 결과를 기록한다. 이번 작업에 해당하는 P1 체크만 갱신한다.

이 작업이 끝나면 **다음 P1 작업은 React 첫 화면의 시계열 CSV 경로(S1-T)**다. React + TypeScript 화면에서 왼쪽 업로드·등록 목록·상태와 오른쪽 행 수·피처 구조를 보여주고, FastAPI를 통해 이번 작업의 등록·분석 서비스를 연결한다. 실제 합성 CSV로 업로드 성공과 실패, 목록에서 다른 데이터셋을 선택했을 때 구조 패널 갱신, 넓고 좁은 창의 가독성을 확인한다. 웹 구성 및 실행법과 함께 `doctor`의 웹 의존성 안내를 FastAPI 기준으로 갱신한다. XLSX, 이미지 구조, 추천 UI와 외부 LLM 공급자 연동은 이후 P1 작업으로 진행한다.
