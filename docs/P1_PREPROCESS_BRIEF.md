# Claude 구현 지시서 — P1 전처리 화면과 Mock 추천

> `CLAUDE.md`, `REQUIREMENTS.md`, `SCREEN_DESIGN.md`의 S1·S2, `CONTRACTS.md`, `PROGRESS.md`와 이 지시서를 읽고 **S2 전처리 화면과 로컬 Mock 추천**을 구현해 줘. 저장된 시계열 목표로 추천을 만들고, 사용자가 이유를 읽고 항목·순서·파라미터를 조정한 뒤 초안을 검증·저장하는 흐름을 실제 브라우저에서 확인해 줘.

## 화면 동작

- S1에서 분석이 끝난 데이터셋의 목표를 저장하면 왼쪽 전처리 메뉴로 진입할 수 있다. 선택한 데이터셋과 목표를 S2에 전달하고, 메뉴 이동 또는 새로고침 후에도 동일한 초안을 불러온다. 목표가 없으면 S1에서 저장할 항목을 안내한다.
- 추천 출처를 **Mock · 오프라인**으로 표시한다. 카드마다 전처리 이름, 무엇을 하는지, 추천 이유, 구현 상태를 한글로 보여준다. 사용자는 체크·해제, 위아래 이동, 스키마에 맞춘 파라미터 편집을 할 수 있다. 고정 순서와 검증 메시지를 해당 항목에서 확인할 수 있어야 한다. 수동으로 시작하거나 다시 추천받을 수 있고, 기존 편집안을 새 추천으로 교체하기 전에 사용자가 선택한다.
- 현재 내장 플러그인이 미구현인 동안에는 등록된 호환 후보를 **계획 미리보기 · 실행 불가**로 분명히 표시한다. 그 안에서 추천 카드 편집과 초안 검증을 확인할 수 있게 한다. 실제 레지스트리의 `ready` 상태와 기존 승인·제출 규칙은 유지한다. 현재 `MockProvider`는 `ready` 모델만 사용하므로, 별도의 로컬 미리보기 경로에서 후보를 만드는 방식과 실제 추천 경로의 경계를 문서화한다. 미등록 또는 비호환 도구는 초안에 적용할 수 없다.

## 추천 요청과 초안 검증

- 추천 입력은 현재 데이터셋 버전의 `SafeProfile`과 저장된 목표로 서버에서 조립한다. 시간열·타깃·설비 구분 열은 보내기 전에 같은 프로파일의 `column_N` 별칭으로 변환한다. 응답의 컬럼 참조는 해당 버전의 사전에서만 복원하고, 존재하지 않거나 다른 버전의 별칭이면 적용을 거부한다. 원본 파일명, 원시 헤더와 셀 값, 서버 경로는 추천 요청에 담지 않는다. 로컬 UI에는 원래 이름을 표시한다.
- React는 추천과 초안 편집 요청을 FastAPI로 보내고, 서버는 기존 Provider·Registry·PlanService의 계약과 초안 검증을 재사용한다. 원래 목표·데이터셋과 일치하는 응답만 쓰고, 초안 리비전 충돌이 나면 최신 상태를 다시 불러오도록 안내한다. 검증 코드·위치·한글 메시지를 화면에서 연결한다.
- S2의 계획 미리보기는 추천과 편집 확인을 뜻한다. 전처리를 실제 데이터에 적용하는 미리보기(D-09), 외부 공급자 호출, 학습 설정 화면, 승인, 학습 실행은 후속 작업이다.

## 완료 확인

- 브라우저에서 CSV 업로드 → 목표 저장 → 전처리 메뉴 → Mock 추천 이유 표시 → 체크·순서·파라미터 수정 → 검증·저장 → 새로고침 후 복원까지 확인한다. 실패 안내와 수동 모드도 확인한다.
- 테스트에서 요청 전체를 검사해 원시 헤더·셀 값·절대경로가 없고, 올바른 별칭만 복원되는지 확인한다. 편집 리비전 충돌, 알 수 없는 도구, 미구현 항목의 승인·실행 차단을 확인한다.
- Python 회귀 테스트, 프런트엔드 빌드, 브라우저 검증을 실행하고 `PROGRESS.md`에 결과를 기록한다. 현재 체크아웃의 `pyproject.toml`에는 `web` extra와 `dev`의 웹 실행·테스트 의존성이 빠져 있다. README의 `.[web]` 및 `.[dev]` 설치 경로가 각각 깨끗한 환경에서 동작하도록 선언과 문서를 맞추고 확인한다.
