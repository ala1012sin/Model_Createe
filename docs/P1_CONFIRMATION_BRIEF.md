# Claude 구현 지시서 — P1 S4 설정 확인·승인

> `CLAUDE.md`, `SCREEN_DESIGN.md` §8, `REQUIREMENTS.md`의 RUN-01, `CONTRACTS.md` §11, `PROGRESS.md`를 읽고 S4의 **계획 요약·최종 검증·승인 상태**를 연결해 줘. P1에서는 명시적 사용자 확인을 기록하는 데까지 진행해 줘.

## 구현 범위

- S3에서 저장한 시계열 초안의 데이터셋과 버전, 목표, 전처리 순서, 모델과 파라미터, 학습량, 분할·평가를 한 화면에서 보여준다. 실제 학습 기간·행 수·소요 시간은 산출된 값이 있을 때 표시한다.
- 서버에서 저장된 초안의 최종 검증을 호출한다. 오류와 경고를 구분하고, 오류를 수정할 S1·S2·S3 입력으로 이동할 수 있게 한다. 미구현 모델과 전처리는 현재 레지스트리 상태대로 승인을 차단한다.
- 이번 화면의 기본 버튼은 **설정 승인**이다. 사용자의 명시적 확인과 예상 리비전을 받아 기존 `PlanService.approve`를 호출한다. 서버가 확인한 승인 상태와 `plan_hash`를 요약에 표시하고, 내부 제출용 승인 토큰은 화면 응답이나 로그에 포함하지 않는다. 기존 `ApprovedSnapshot`과 승인 무효화 로직을 재사용한다. 실행 설정이 바뀌면 새로 승인이 필요하다고 표시한다. P2에서 실제 제출이 연결될 때 학습 시작 버튼을 활성화한다.
- 테스트에서만 실행 가능 레지스트리를 주입한다. 실제 내장 Registry나 ADD 어댑터 등록 경로에 테스트용 ready 처리를 넣지 않는다. 공유 폴더에 반영하기 전에 수정 대상 파일의 현재 상태를 확인하고 ADD-1·ADD-2와 다른 작업에서 들어온 변경을 병합한다.

## 완료 확인

- 실제 브라우저에서 S3 저장 → S4 요약 → 미구현 후보의 승인 차단 → 조치할 단계로 돌아가기까지 확인한다.
- 실행 가능 테스트 목록으로 정상 승인·해시 재조회, 잘못된 리비전 거부, 실행 설정 변경 후 승인 무효화, 경고만 있을 때의 승인 흐름을 확인한다. 이 단계에서 새 실행 기록이 생성되지 않아야 한다.
- Python 회귀 테스트와 프런트엔드 빌드·브라우저 검증 결과를 `PROGRESS.md`에 추가한다.
