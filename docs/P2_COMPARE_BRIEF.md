# S6 실험 비교 — 설계 기록 (2026-11-20, Claude 작성)

> 사용자 지시(대화): 우선순위 ⑤ S6 실험 비교, "일단은 진행해보자". 별도 지시서가 없어 규칙 14에 따라 구현 전에 기록한다.
> 근거: REQUIREMENTS RESULT-01, SCREEN_DESIGN §9 "S6 결과 비교 탭", ARCHITECTURE §8 "데이터셋/스플릿/GT/metric protocol이 다르면 경고,
> 동일 지표처럼 보이는 숫자의 무분별한 순위 매기기 금지". PROGRESS P5 "동일 조건 실험 비교, 프로토콜이 다르면 경고"를 앞당긴다.

## 완료 범위(시계열)

1. 실행·결과 목록 = 비교 표: 체크박스 선택, 데이터셋 필터, 전처리 요약·예측 시점·소요 시간 열, 처음 고른 실행(기준)과 **평가 조건이 다르면 ⚠**,
   "같은 평가 조건만" 보기.
2. 2~6개 선택 시 비교 패널: 평가 조건 경고, **조건 차이**(다른 항목만), 지표(전체·예측 시점별·설비별, 같은 조건끼리만 최고값 표시),
   **실제 vs 예측 그래프**(테스트 구간, 예측 시점·설비 선택), 각 실행의 상세·새 데이터 적용 링크.
3. API `GET /api/runs/compare`, `GET /api/runs/compare/series`.

범위 밖: 실행 이름 붙이기·삭제(ADD-UX-06·07), 설정 복제해 재실험, 비전 지표, MCP `experiment.compare`(P5 유지).

## 설계

| 항목 | 결정 | 이유 |
|---|---|---|
| 평가 조건(프로토콜) | 데이터셋 버전(내용 해시) · 타깃·시간열·설비 열 · 분할 비율·gap · 평가 지표·기준 예측 · **테스트 표본 집합**(예측 저장 파일의 테스트 행 (설비, 기준 시각, 예측 시점) 정렬 해시, 예측 시점별 표본 수) | 숫자가 같은 표본·같은 정답으로 계산됐을 때만 순위를 매긴다. 분할 비율이 같아도 리샘플 간격 등으로 표본이 달라질 수 있어 실제 표본 집합으로 판단 |
| 조건 차이(실험 변수) | 전처리 단계·파라미터, 모델·파라미터, 학습량, 사용자 플러그인 코드 해시 | 사용자가 바꿔 본 것 — 경고가 아니라 차이로 보여 줌 |
| 기준 실행 | 처음 체크한 실행. 다른 실행이 기준과 평가 조건이 다르면 ⚠ + 다른 항목. 최고값 표시는 기준과 같은 조건인 실행끼리만 | ARCHITECTURE §8 |
| 예측 시점이 다를 때 | '전체' 지표는 조건 다름으로 표시, 공통 예측 시점별 행은 그 시점의 표본 집합이 같으면 비교 | |
| 계산 위치 | `app/compare.py` 순수 함수 + 실행 폴더의 `compare_key.json` 캐시(완료 실행만, 파일이 바뀌면 다시 계산) | 목록은 3초마다 갱신되므로 매번 예측 파일을 읽지 않음 |
| 그래프 | 서버가 테스트 구간 한 설비·한 예측 시점의 (대상 시각, 실제, 실행별 예측)을 같은 표본끼리 맞춰 최대 600점(균등 간격 추출)으로 보냄. 화면은 SVG 선 그래프(외부 라이브러리 없음) | 의존성 최소화 |
| 표시 | RunView에 `steps`(전처리 표시 이름 목록)·`protocol_key`(평가 조건 짧은 해시)·`duration_s` 추가 | |
