# Claude 구현 지시서 — XLSX 등록·시트 선택·학습·새 데이터 적용

> 루트 `CLAUDE.md`, `docs/CLAUDE.md`, `docs/CONTRACTS.md`, `docs/SCREEN_DESIGN.md`의 S1·S7, `docs/PROGRESS.md`와 이 지시서를 읽고 **XLSX 업로드 → 시트 선택 → 구조 확인 → 기존 시계열 학습 → S7에서 새 XLSX 예측·다운로드**를 연결해 줘. 실제 코드를 먼저 조사하고 기존 CSV 서비스·프로파일·전처리·모델·실행기를 재사용해 줘.

## 기존 코드와 연결 지점

`DatasetManifest`에는 `source_kind=xlsx`와 `selected_sheet`가 있으나, 실제 등록은 `register_csv`와 `source.csv` 경로를 사용한다. worker도 `source.csv`를 읽으며 `FittedTimeseries`와 S7 점검은 CSV 입력을 사용한다. 엑셀을 읽는 코드는 입력 어댑터에 두고, 선택한 시트를 공통 표 데이터로 정규화해 이 경로에 연결한다. 파일 확장자만 XLSX로 허용하는 것으로 끝내지 않는다.

## 이번 입력 정책

- 표 형식의 `.xlsx`를 지원한다. CSV 입력 동작을 보존하고 지원 형식을 파일 선택 영역에 안내한다. 매크로·구형 XLS 등은 현재 지원 형식에 맞는 한글 안내를 제공한다.
- 원본을 로컬 작업 공간에 보관하고 시트 이름·표시 상태를 조회한다. 사용자가 고른 시트만 프로파일링한다. S1에 선택한 시트, 실제 읽은 행·열 수, 피처 타입·결측률·시간 후보를 표시한다. 이름은 로컬 화면에서만 사용한다.
- 첫 비어 있지 않은 행을 헤더로 사용한다. 헤더와 데이터 사이 완전 빈 행, 중간 빈 셀, 끝의 빈 행·열 처리 기준을 정하고 제외 수를 기록한다. 헤더가 비어 있거나 중복이면 해당 위치와 수정 방법을 안내한다. 병합 셀 때문에 표의 헤더·데이터 해석이 모호하면 병합 해제와 값 채우기를 안내한다.
- Excel 날짜 타입과 1900/1904 날짜 기준을 지원 라이브러리로 해석하고, 시간대 없는 날짜를 기존 입력 정책에 맞는 값으로 변환한다. 텍스트 ID의 앞자리 0을 보존한다. 숫자 표시 형식과 실제 저장값이 다른 경우 처리 정책을 문서화한다. 서식만 있는 끝 셀이 데이터 행 수를 부풀리지 않게 한다.
- 수식은 실행하지 않고 **파일에 저장된 계산 결과**를 읽는다. 데이터 범위 안의 수식에 저장 결과가 없거나 Excel 오류 값이 있으면 위치와 해결 방법을 알려준다. 사용자가 Excel에서 다시 계산하고 저장하도록 안내하며 빈 값·0으로 조용히 대체하지 않는다. 저장 결과의 최신성은 앱이 보장할 수 없으므로 수식이 있는 시트에는 저장된 결과를 사용한다는 안내를 표시한다.

## 버전·승인·재사용

- 원본 파일 내용 해시, 선택 시트, 표 정규화 규칙과 생성한 표의 내용 해시를 기록한다. 승인과 실행은 같은 선택·같은 표 데이터에 결합되어야 한다. 정규화 파일을 원본 XLSX의 내용 해시와 혼동하지 않도록 기존 버전 검증 경로를 확인한다.
- 이미 목표·전처리·승인이 있는 데이터의 시트를 바꾸면 이전 설정을 그대로 실행할 수 없어야 한다. 다른 시트는 새 논리 데이터셋으로 만들거나, 기존 버전 변경·목표 재확인·승인 무효화를 원자적으로 적용하는 방식 중 현재 서비스에 맞는 방법을 계약에 기록한다. 이미 시작된 실행과 과거 결과는 당시 데이터 버전을 유지한다.
- CSV 프로파일과 학습·S7이 읽는 공통 표를 기존 서비스에서 제공한다. 재시작·재시도 시에도 원본과 선택한 시트·정규화 결과를 추적할 수 있어야 한다. 저장 실패나 변환 실패가 성공 프로파일로 보이지 않게 한다.
- SafeProfile과 추천 목표에는 기존 별칭 정책을 적용한다. 원본 워크북·시트 이름·수식 문자열·셀 값·서버 경로가 LLM 요청으로 들어가지 않는지 확인한다.
- XLSX 읽기 의존성은 optional extra에 선언하고 설치되지 않으면 설치할 옵션을 알려준다. 실제 설치는 환경과 기존 세션 승인 범위에 따라 진행한다. ZIP 형식의 XLSX는 기존 업로드 제한과 압축된 항목의 해제 크기를 점검하고, 외부 링크를 열거나 사용자 코드를 실행하지 않는다.

## S7 새 엑셀 적용

- S7에서도 XLSX를 올리고 시트를 고른 뒤 저장 모델의 필요한 열과 과거 이력을 점검한다. 이후 기간 파일의 시트 이름은 학습 당시 시트 이름과 달라도 필요한 입력 열과 데이터 조건이 맞으면 적용할 수 있다.
- 기존 입력 점검·모델 무결성 검사·저장 상태를 이용한 변환·추론을 그대로 사용한다. 새 엑셀에 모델이나 스케일러를 다시 fit하지 않는다. 점검 뒤 시트나 파일이 바뀌면 새 입력 버전으로 다시 점검한다.
- 결과 다운로드는 기존 CSV 형식과 모델 버전 메타데이터를 사용한다. 적용 기록에 실제 선택한 입력 시트와 원본·변환 데이터 버전을 남긴다.

## 완료 확인

- 같은 데이터의 CSV와 XLSX로 등록해 행·열·타입·결측 수와 시각 해석을 비교한다. 선택한 데이터의 의미가 같을 때 동일 설정·seed로 학습한 분할·예측·지표가 허용 오차 안에서 일치해야 한다.
- 테스트용 여러 시트 워크북으로 목록·선택·전환을 확인한다. 날짜 셀, 1904 날짜 기준, 한글·텍스트 ID, 수식의 저장 결과 유무, Excel 오류 값, 빈·중복 헤더, 병합·빈 시트와 서식만 있는 끝 셀을 확인한다. 이전 시트의 프로파일·승인을 새 시트에서 재사용하지 않는지 확인한다.
- 브라우저에서 XLSX 업로드 → 시트 선택 → S1 목표 → S2 전처리 → S3 최근 30일·70/15/15·MAE/RMSE → S4 승인 → S5 완료를 확인한다. S7에서는 학습 이후 기간의 XLSX를 선택해 시트 점검·예측·CSV 다운로드를 확인한다. 같은 내용의 CSV 적용 결과와도 비교한다.
- 기존 CSV·rolling·차분·시간 특징·학습·S7과 승인 회귀 테스트, 프런트엔드 빌드, 넓고 좁은 창의 브라우저 검증을 실행한다. 테스트용 워크북은 재현 가능한 기준으로 생성하고 생성 방법을 남긴다.
- 변경·정책·테스트·실제 실행 증거를 [PROGRESS.md](PROGRESS.md)에 추가한다. XLSX 관련 체크만 실제 결과대로 갱신한다. 다음 남은 작업은 사용자 정의 플러그인 예제와 최소 대기열이다.
