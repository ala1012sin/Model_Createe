# Claude 구현 지시서 — P2 S7 새 CSV 예측·내려받기

## 작업 지시

> 루트 `CLAUDE.md`, `docs/CLAUDE.md`, `docs/CONTRACTS.md`, `docs/SCREEN_DESIGN.md`의 S7, `docs/PROGRESS.md`와 이 문서를 읽고 **완료된 실행 선택 → 새 CSV 입력 조건 확인 → 저장 모델로 예측 → CSV 다운로드**를 구현해 줘. 기존 `FittedTimeseries.load`와 `predict_csv`를 재사용하고, 현재 S5에서 S7로 이어지는 동선을 연결해 줘. 저장한 전처리 상태와 모델로 추론하며 학습을 다시 수행하지 않아야 해.

이번 작업은 시계열 CSV 경로다. 실제 모델 성능 수치는 테스트에서 측정한 값으로 기록한다. 명령은 프로젝트 루트에서 실행한다.

## 기존 기능 재사용

- `pipelines/timeseries.py`의 저장 파이프라인과 모델 로딩·예측 함수를 먼저 확인한다. 새 실행기를 복제하지 않고 기존 모델·전처리 어댑터를 사용한다.
- 완료된 `run_id`와 `plan_hash`를 모델 버전 식별에 사용한다. 화면에는 원본 데이터셋·모델·완료 시각으로 선택지를 보여준다. 현재 편집 중인 초안이나 이후 바뀐 기본값이 추론 설정에 들어가지 않아야 한다.
- CSV의 저장·인코딩·구분자·파일 크기 정책과 한글 오류 처리는 기존 등록 서비스를 활용한다. 입력 점검과 결과 저장은 Application Service에 두고 FastAPI에서 호출한다. MCP 노출은 후속 범위다.

## 화면 동작

1. S5 완료 실행의 **새 데이터에 적용** 또는 왼쪽 **새 데이터 적용** 메뉴에서 S7로 진입한다. 완료 모델이 없으면 학습을 완료할 경로를 안내한다. 실패·취소 실행은 선택할 수 없다.
2. 선택한 모델의 목표, horizon, 필요한 입력 열, 저장된 전처리와 과거 관측 요구를 한글로 보여준다. 새 CSV를 올리면 누락 열·시각 해석·유효 행·관측 이력 부족을 점검한다.
3. 사용자가 **예측 실행**을 누르면 입력 점검에 사용한 같은 데이터 버전과 모델로 추론한다. 실행 중 상태와 실패 이유를 표시하고, 예측이 끝나면 건수·설비·기간·horizon 및 결과 일부와 CSV 다운로드를 제공한다.
4. 모델이나 입력 파일을 바꾸면 이전 점검·결과와 현재 선택을 구분한다. 페이지를 다시 열어도 완료된 적용 기록에서 사용한 입력과 모델, 결과를 확인할 수 있게 한다. 상단 바·검색과 다른 화면에서 저장한 설정을 보존한다.

## 입력·예측 계약

- 현재 `load_frame`은 시간열·그룹열과 저장한 수치 입력 열을 사용하고 과거 타깃도 요구한다. 입력 요구사항은 실제 저장 파이프라인에서 계산한다. 과거 타깃이 피처 또는 lag에 사용되면 반드시 필요하다고 설명한다. 예측 대상 시각의 미래 실제값은 예측 조건으로 요구하지 않는다.
- 첫 버전은 학습 당시 열 이름과 같은 CSV를 받는다. 열 매핑이 필요하면 부족한 이름과 필요한 이름을 보여준다. 컬럼 순서가 달라도 동일한 입력을 구성하고, 추가 열은 명시한 정책에 따라 처리한다. 문자열·범주 열의 기존 제외 정책도 표시한다.
- 학습 때의 시간대·중복 시각·리샘플·세션·결측 처리와 동일한 정책을 적용한다. 이력이 부족한 초기 행 또는 유효 피처가 없는 행은 이유와 건수를 알려준다. 예측 가능한 행이 0개면 모델 호출 전에 사용자에게 조치할 항목을 알려준다.
- 시계열 모델은 horizon별로 저장되어 있으므로 각각의 기준 시각과 예측 대상 시각을 유지한다. 마지막 관측 이후의 시각에도 입력 피처가 충분하면 예측할 수 있어야 한다. 미래 관측을 요구하는 라벨 결합이 추론에 섞이지 않는지 확인한다.
- 모든 fit 호출을 막은 테스트에서도 추론이 성공해야 한다. 저장 모델·전처리 파일의 누락·불완전한 상태·호환되지 않는 형식·필수 라이브러리 부재를 오류로 처리한다. 저장된 상태 개수와 단계 개수가 다르면 `zip`으로 조용히 잘리지 않도록 검사한다.
- 원본 학습 실행과 입력 파일을 덮어쓰지 않는다. 적용 기록에는 원본 실행·해시, 입력 내용 해시와 해석 정책, 추론 상태·시각·결과 참조를 남긴다. 실패한 작업이 성공 결과로 노출되지 않도록 한다.
- 결과 CSV에는 모델의 `run_id`·`plan_hash`, 설비, 기준 시각, 예측 대상 시각, horizon, 예측값을 남긴다. 서버 경로나 내부 승인 토큰은 응답에 포함하지 않는다. 다운로드는 해당 적용 기록의 완료 결과를 제공한다.

## 실행과 Windows 확인

- 추론 중에도 목록·상태 API가 응답하도록 기존 프로세스 관리 구조를 활용한다. 저장된 모델은 필요한 구현만 불러오며 학습용 프로세스를 다시 시작하지 않는다. 예측 실패·앱 종료·재시작 시 적용 상태를 정리한다.
- Windows에서 사용할 의존성이 준비되어 있으면 `tests/integration/test_runs.py`의 실제 학습 프로세스 실행·중복 요청·취소·종료·재시작 경로를 먼저 확인한다. `ctypes`로 Windows 프로세스 핸들을 다루는 부분은 64비트 핸들과 함수 인자·반환 형식을 확인한다. 실제 Chrome과 WebView2에서도 S5에서 S7로 이동해 확인한다.
- 추가 설치가 필요하면 필요한 패키지와 환경을 구체적으로 확인하고 세션의 승인 범위에 따라 진행한다. Windows 확인을 수행하지 못하면 실행한 Linux 검증과 구분해 기록한다.

## 검증과 완료 기준

- 학습용 `motor_sensor_example.csv`로 완료 모델을 만든 뒤, 학습 때와 다른 이후 기간의 합성 CSV를 준비해 S5 → S7 → 입력 점검 → 예측 → 다운로드를 실제 브라우저에서 확인한다. 합성 예제의 생성 기준을 기록한다.
- 같은 원본 CSV를 다시 적용할 때 저장된 평가 예측의 동일 설비·기준 시각·대상 시각·horizon 행을 조인하여 허용 오차 안에서 일치하는지 확인한다. 평가 구간 외의 추론 표본이 포함될 수 있으므로 행 수만으로 비교하지 않는다.
- 빠진 열, 과거 타깃 부재, 열 순서 변경·추가 열, 이력 부족·0표본, 시간대 형식 충돌, 손상 모델과 입력·모델 변경 후 재점검을 테스트한다. 원본 실행의 설정·모델·지표가 변하지 않고 학습 실행 건수가 늘지 않는지 확인한다.
- 기존 회귀 테스트와 프런트엔드 빌드, 새 입력 점검·추론 API 테스트, 넓고 좁은 창의 S7 브라우저 검증을 실행한다. 새 다운로드의 값과 메타데이터를 확인한다.
- 변경·테스트·실제 적용 증거를 [PROGRESS.md](PROGRESS.md)에 추가한다. 새 CSV 예측·다운로드 항목을 완료로 바꾸고, XLSX·대기열 등 남아 있는 P2 세부 항목은 실제 구현 상태대로 유지한다.
