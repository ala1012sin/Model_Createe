# P2 사용자 정의 전처리 플러그인 예제 — 설계 기록 (2026-11-20, Claude 작성)

> 사용자 지시(대화): "고고 그리고 검증도 일단 너가 해줘야돼". 별도 지시서가 없어 CLAUDE.md 규칙 14에 따라
> 구현 전에 설계·대안·영향을 이 문서에 먼저 기록한다. 근거: ARCHITECTURE §7 "모듈 확장", CONTRACTS §7 "플러그인 계약",
> PROGRESS P2 "사용자 정의 `ts.custom_feature` 플러그인 1개 추가 및 자동 노출".

## 1. 완료 범위

예제 플러그인 폴더 하나를 두면 **core 코드 수정 없이** 다음이 같은 경로로 연결된다.

1. Registry 자동 발견 → `mlwb doctor` 표시
2. S2 전처리 추가 목록·카드(“사용자 정의” 표시)·파라미터 편집·검증
3. 추천 후보: LLM에 주는 읽기 전용 카탈로그(`catalog.list_preprocessors`)에 포함
4. S4 확정 → 실행(worker 서브프로세스) → 지표·예측 저장
5. S7: 저장 모델을 불러와 새 데이터에 **같은 피처**를 만들어 예측

예제: `plugins/ts_custom_ewm/` — `ts.custom.ewm` "지수 가중 평균(EWM)". 같은 설비·세션 안에서 현재 시점을 제외한
과거 관측의 지수 가중 평균(span)을 피처로 추가한다(내장 rolling과 겹치지 않는 실제 쓸모가 있는 피처).

범위 밖: 플러그인 설치·업로드 UI, zip/원격 다운로드, 자동 `pip install`, LLM 생성 코드 실행, 비전 플러그인, 모델 플러그인.

## 2. 설계

| 항목 | 결정 | 대안·이유 |
|---|---|---|
| 위치 | 기본 `<프로젝트>/plugins/<폴더>/`. 환경변수 `MLWB_PLUGIN_DIRS`(경로 구분자 `;`/`:`)가 있으면 그것만, 빈 값이면 사용자 플러그인 없음 | 작업 공간(`workspace/`)은 데이터 폴더라 코드와 분리. 서버·worker·CLI가 같은 규칙으로 찾는다 |
| 형식 | `plugin.json`(PluginSpec 필드 + `entry: "plugin.py:ClassName"`) + 같은 폴더의 `.py` | 명세를 먼저 검증한 뒤에만 코드를 불러온다 |
| 신뢰 모델 | **사용자가 직접 둔 로컬 코드만** 실행(신뢰된 로컬 플러그인). 하위 폴더 밖 파일·심볼릭 링크 entry 거부 | ARCHITECTURE §7. 샌드박스가 아님을 문서에 명시 |
| ID 규칙 | `ts.custom.<이름>`만 허용 | 내장 ID를 덮어쓰거나 흉내 내지 못하게 |
| 범위 | `kind=preprocessor`, `modality=timeseries`, 입출력 `table.timeseries`, `fit_scope` stateless/train_only | 모델 플러그인은 P4 |
| 실패 처리 | 명세는 맞는데 코드 불러오기 실패·필수 메서드 없음 → `status=invalid` + 사유로 등록(보이지만 실행 불가). 명세 자체가 틀림·ID 충돌 → 등록하지 않고 "불러오기 문제" 목록(폴더 이름+사유, 절대경로 없음) | CONTRACTS §7 "로드하지 않고 사용 불가 사유 노출" |
| 의존성 | 명세 `dependencies`가 없으면 `missing_dependency`(기존 규칙). 설치는 하지 않음 | |
| 코드 해시 | 폴더의 `plugin.json`+`*.py` 내용 해시 `code_sha256`. 승인 스냅샷 `plugin_code`, 실행 산출물 `pipeline.json`·`environment.json`에 기록. 제출·worker 시작·S7 불러오기에서 현재 코드와 다르면 `PLUGIN_CODE_CHANGED`로 거절 | 버전을 올리지 않고 코드를 고쳐도 승인한 코드로만 실행되게 |
| 안전 장치(실행) | 사용자 플러그인은 래퍼를 거친다: ① 라벨 열(`__label`, 미래 정답) 숨김 ② 행 수·순서·시간·설비·세션·기존 열 변경 금지 ③ 새 피처 이름 중복·예약어 금지, 수치형만 ④ train_only 상태는 JSON 저장 가능해야 함 ⑤ **과거만 사용 검사**: 설비마다 앞부분만 잘라 다시 계산해 겹치는 행의 피처가 같아야 함(다르면 `PLUGIN_FUTURE_LEAK`) | 내장은 코드 검토로 보장, 사용자 코드는 실행 시 검사 |
| 이력 요구 | 어댑터 선택 메서드 `history(params, target) -> (칸 수, {열: 설명})`. S7 요구사항 표시가 ID 하드코딩 대신 이 값을 쓴다(내장 lag·rolling·차분도 같은 방식으로 전환, 표시 결과 동일) | core가 사용자 ID를 몰라도 S7 안내 가능 |
| 화면 | 카드·추가 목록에 "사용자 정의" 표시, 불러오기 문제는 S2 상단 안내 | |

## 3. 검증 계획(이번에는 Claude가 실행)

- 단위: 발견·명세 오류·ID 규칙·충돌·entry 경로 탈출·import 오류·메서드 누락·의존성 없음·스키마 오류·환경변수 끄기,
  래퍼(라벨 숨김, 행/기존 열 변경 거부, 이름 충돌, 미래 사용 탐지), EWM 계산값 수작업 대조.
- 통합: S2 카탈로그·LLM 카탈로그 노출, 초안 검증, 확정 → 실제 worker 학습, S7 같은 피처·예측 일치(학습 평가 예측과 재적용 결과 비교),
  승인 후 코드 변경 → 제출 거절, 학습 후 코드 변경 → S7 거절, 플러그인 폴더 제거 → 실행 불가 표시.
- 브라우저: S2에서 추가 → 확정 → 학습 → S7 예측·내려받기.
- 회귀: 전체 pytest(작업 공간·PC), 기존 브라우저 점검, `tsc`·`vite build`. Windows는 실행 환경이 없어 미실행으로 기록.
