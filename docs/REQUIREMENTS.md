# ML Workbench 요구사항 정의서

개인용 한글 ML 워크벤치의 화면 요구사항이다. 사용자가 데이터 구조를 확인하고, 전처리와 평가 방식을 정해 학습한 뒤, 선택한 모델을 새 데이터에 적용할 수 있어야 한다.

## 1. 기본 사용 흐름

**데이터셋 업로드·확인 → 전처리 추천·선택 → 학습량·평가 설정 → 설정 확인·학습 실행 → 진행·결과 확인 → 모델 선택·새 데이터에 적용**

## 2. 화면별 요구사항

| ID | 단계 | 사용자 요구사항 및 확인 기준 |
|---|---|---|
| DATA-01 | 데이터셋 | 앱의 첫 화면이다. 왼쪽에서 데이터셋을 업로드하고, 업로드 중·분석 중·완료·실패 상태와 등록된 항목을 볼 수 있다. 오른쪽에는 현재 선택한 데이터셋의 구조가 표시된다. |
| DATA-02 | 시계열 구조 | CSV 또는 XLSX를 선택하면 오른쪽에 행 수와 피처 목록 및 타입(예: 시간·수치·범주형)이 표시된다. XLSX는 선택한 시트를 기준으로 보여준다. 사용자가 시간열, 예측 타깃, 필요 시 설비 구분 열과 예측 구간을 확인한다. |
| DATA-03 | 이미지 구조 | 이미지 폴더 또는 ZIP을 선택하면 오른쪽에 폴더 트리와 예시 이미지 1~2장을 표시한다. 예시를 표시할 수 없으면 이유를 안내한다. 폴더명으로 추정한 정상·불량·라벨 구조는 사용자가 확인할 수 있어야 한다. |
| PREP-01 | 전처리 추천 | 전처리 탭에 들어가면 선택한 데이터셋과 목표에 대한 LLM 기본 추천을 확인할 수 있다. 항목별로 무엇을 하는지와 이 데이터에 왜 추천하는지를 한글로 표시한다. |
| PREP-02 | 전처리 선택 | 사용자가 추천 항목을 체크하거나 해제하고, 필요한 파라미터를 편집할 수 있다. 필요한 경우 순서를 조정한다. 실행할 항목과 순서가 명확히 보이며, 호환되지 않는 조합은 이유를 표시한다. 추천 실패나 LLM 미연결 시 수동으로 선택할 수 있다. |
| TRAIN-01 | 학습 데이터량 | 학습 전 사용량을 선택한다. 시계열은 전체 또는 최근 N일, 비전 이상탐지는 정상 학습 이미지 전체 또는 N장부터 지원한다. 사용량 변경은 학습 구간에 적용하며, 비교할 검증·테스트 구간은 유지한다. 실행 기록에는 실제 사용 기간 또는 이미지 수와 재현에 필요한 선택 정보를 남긴다. |
| EVAL-01 | 평가 선택 | 학습 실행 전에 평가 방식을 고를 수 있다. 시계열은 시간순 분할, MAE/RMSE, 기준 예측을 선택하는 흐름을 제공한다. 비전 이상탐지는 이미지 지표와 필요한 경우 보정 데이터 기반 판정 임계값 규칙을 설정한다. GT 마스크가 필요한 픽셀 지표에 대해 GT가 없으면 적용 불가 사유를 표시한다. |
| EVAL-02 | 개인 기본값 | 태스크별 평가 설정과 학습량 기본값을 저장해 다음 실험에 불러오고, 실험별로 변경할 수 있다. 이전 실행에서는 당시 확정한 설정을 확인할 수 있다. |
| RUN-01 | 학습 실행 | 실행 전에 데이터셋, 모델, 선택한 전처리, 학습량, 평가 방식을 한 화면에서 확인한다. 사용자가 확정한 뒤에 시작하며, 실행을 막는 오류는 조치할 항목과 이유를 표시한다. |
| RUN-02 | 진행 확인 | 실행 후 대기·실행 중·완료·실패·취소 상태와 현재 단계(예: 전처리, 학습, 평가)를 한글로 보여준다. 진행률을 계산할 수 있으면 표시하고, 그 외에는 현재 단계와 경과 시간을 표시한다. 단계와 상태는 실행기의 실제 이벤트를 기준으로 갱신한다. |
| RESULT-01 | 결과 비교 | 사용자가 학습량·평가 조건·지표·소요 시간을 확인하고 실험을 비교할 수 있다. 분할이나 평가 기준이 다르면 차이를 표시한다. |
| APPLY-01 | 새 데이터 적용 | 비교 결과에서 다시 쓸 모델 버전을 선택하고, 새 CSV나 이미지에 적용할 수 있다. 필요한 입력 조건과 부족한 항목을 안내하고, 시계열 예측값 또는 이미지 점수·판정을 확인하고 내려받을 수 있다. 결과에 사용한 모델 버전을 남긴다. |

## 3. 공통 동작

- 앱의 맨 왼쪽에 세로 탐색 메뉴를 두고 아이콘과 짧은 한글 이름으로 작업 화면을 이동한다. 데이터셋 화면에서는 탐색 메뉴 오른쪽에 업로드·등록 목록, 그 오른쪽에 선택한 데이터의 구조를 보여준다. 현재 메뉴와 아직 진입할 수 없는 메뉴는 상태를 구분해 표시한다.
- 일상 작업은 한글 워크벤치에서 완료할 수 있어야 한다. MLflow를 연동하는 경우 기록과 모델 버전의 기반으로 사용하며, 사용자가 일반 작업 중 별도 MLflow 화면을 열 필요가 없어야 한다.
- 전처리 추천에 외부 LLM을 사용한다면 전송할 요약과 전송 허용 여부를 확인할 수 있어야 한다. 이미지 미리보기는 로컬 데이터 탐색 기능이다.
- 학습 결과를 새 데이터에 적용할 때 선택한 모델 버전과 함께 저장된 전처리, 입력 조건, 필요한 판정 임계값을 사용한다.

## 4. Claude에 전달할 화면 설계 작업

> `REQUIREMENTS.md`, `ARCHITECTURE.md`, `CONTRACTS.md`, `PROGRESS.md`를 읽고 `SCREEN_DESIGN.md`를 작성해 줘. 위 요구사항 ID를 화면별로 연결하고, 각 화면의 목적, 주요 구성 요소, 사용자 동작, 화면 전환, 빈 상태·로딩·오류 상태를 한글로 적어 줘. 첫 화면은 왼쪽 업로드·등록 목록과 오른쪽 데이터 구조로 구성하고, 시계열과 이미지 예시를 각각 와이어프레임으로 보여줘. 전처리 탭은 추천 이유와 체크 선택을 표시하고, 평가 선택을 마친 뒤 학습을 실행해 실제 진행 단계를 확인할 수 있도록 설계해 줘. 결과 비교에서 모델을 선택해 새 데이터에 적용하고 다운로드하는 경로도 포함해 줘. 평가와 학습량을 전용 단계로 둘지 학습 설정에 묶을지 등의 배치 결정은 근거와 함께 기록해 줘. 기존 계약과 충돌하는 부분은 설계서에 결정 필요 항목으로 남겨 줘. 이번 작업의 산출물은 화면 설계서야.

설계 검토 시 시계열 CSV와 이미지 데이터 각각에 대해 업로드부터 학습 실행까지 화면을 따라갈 수 있는지, 시계열 결과에서 선택한 모델로 새 CSV를 예측하고 내려받는 경로가 이어지는지 확인한다.

## 5. 추가 요구사항 (2026-11-20, Windows 앱 사용 확인 중 요청)

적용 시점: 계획한 P2 작업(최소 대기열 → S6 실험 비교)을 마친 뒤 한꺼번에 적용한다. 진행·결과는 `PROGRESS.md`에 기록한다.

적용 현황(설계 `ADD_UX_BRIEF.md`): **1차 완료(2026-11-20) — 03·04·05·08·09·10·11**, **2차 완료(2026-11-20) — 02·06·07**(실행 삭제 시 그 모델의 새 데이터 적용 기록도 함께 삭제 — 사용자 결정). 남은 것: 3차 01(자동 설치).

| ID | 단계 | 사용자 요구사항 및 확인 기준 |
|---|---|---|
| ADD-UX-01 | 설치 | 앱 실행기(cmd)로 켤 때 빠진 선택 패키지(예: 엑셀용 openpyxl)를 자동으로 설치한다. 무엇을 설치하는지 보여 주고, 네트워크·프록시 문제로 실패하면 수동 설치 명령을 안내한다. 프로젝트 `.venv`에만 설치한다. |
| ADD-UX-02 | 데이터셋 | 데이터셋을 삭제할 수 있다. 학습 실행이 있으면 확인 창에 '학습 실행 N개·모델·예측 결과도 함께 삭제'를 보여 주고 체크해야 삭제한다. 진행·대기 중인 학습이 있으면 삭제할 수 없다. |
| ADD-UX-03 | 공통 | 앱 창 닫기(×)를 누르면 종료 확인을 보여 준다. 진행·대기 중인 학습이 있으면 중단된다는 것을 함께 알린다. |
| ADD-UX-04 | 학습 설정 | 모델 파라미터 입력란에 기본값(XGBoost 트리 300 · 깊이 6 · 학습률 0.1)을 보여 주고, 기본값으로 되돌릴 수 있다. |
| ADD-UX-05 | 데이터셋 | (버그) 업로드에 실패한 엑셀 데이터셋은 목록에서 '시트 선택 필요'가 아니라 '업로드 실패'로 표시한다. |
| ADD-UX-06 | 결과 | 학습 실행마다 이름(메모)을 붙이고 바꿀 수 있다. 실행 목록에 이름·전처리 요약(예: lag·EWM 포함)·예측 시점을 함께 보여 주고, 새 데이터 적용의 모델 선택에도 같은 이름을 쓴다. |
| ADD-UX-07 | 결과 | 학습 실행을 삭제할 수 있다(확인 후 모델·예측·로그 함께 삭제). 진행·대기 중인 실행은 삭제 대신 취소한다. 그 모델로 만든 새 데이터 적용 기록의 처리는 설계 때 정한다. |
| ADD-UX-08 | 공통 | 데이터셋이나 화면 내용이 바뀌어도 박스 위치·폭이 흔들리지 않게 고정한다(세로 스크롤바 유무에 따른 폭 변화 등). |
| ADD-UX-09 | 데이터셋 | '목표 저장'을 누르면 '저장했습니다' 알림을 잠깐 보여 주고 전처리 화면으로 자동 이동한다. 다른 단계의 '저장하고 다음으로' 흐름과 맞춘다. |
| ADD-UX-10 | 공통 | 각 화면에 뒤로가기(이전 단계로)를 둔다. 예: 실행 상세 → 실행 목록, 전처리 → 데이터셋·목표, 학습 설정 → 전처리. 지금은 상단 경로 링크(실행·결과 ›)나 왼쪽 메뉴로만 돌아갈 수 있다. 앱 창(브라우저 뒤로가기 버튼 없음)에서도 같은 동작. |
| ADD-UX-11 | 전처리 | 시간 간격 파라미터(세션 분리 gap, 리샘플 간격, 결측 최대 채움 간격 등)는 숫자만 입력하고 단위는 고르게 한다(예: 숫자 60 + 단위 '분' 선택 → 내부 값 60min). 지금은 '60'만 넣으면 '형식이 올바르지 않습니다(예: 15min)' 오류. 기본 단위는 분. |
